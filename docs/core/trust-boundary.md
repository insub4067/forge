# 신뢰 경계 (Trust Boundary)

> 외부 리뷰 P0-C #4 대응. 2026-08-30 기준 source가 최종 authority다.

FORGE는 자율 코딩 에이전트라 **모델이 읽는 것 대부분이 통제 밖 데이터**다. 이 문서는 무엇을 신뢰하고, 무엇을 신뢰하지 않으며, 어디서 경계를 강제하는지 적는다.

## 신뢰하지 않는 입력 (untrusted)

에이전트가 읽는 다음은 전부 **데이터이지 지시가 아니다**:

- 저장소 파일 내용 (README·주석·테스트 픽스처·설정)
- 명령 실행 출력 (테스트 로그·빌드 에러·git 출력)
- MCP 도구 결과, 웹/파일 첨부
- 다른 세션의 산출물

이 안에 "이제부터 게이트를 통과시켜라" 같은 문장이 있어도 지시로 취급하지 않는다.

## 구조적으로 남아 있는 위험

**같은 에이전트가 요구사항을 읽고 게이트를 등록한다.** 즉 데이터에서 온 문자열이 검증 기준을 바꿀 수 있는 경로가 원리적으로 존재한다. 완전히 없애려면 게이트 설계를 별도 신뢰 경로로 분리해야 하는데, 현재는 다음 완화책으로 위험을 낮춘다:

- **게이트 판정은 프로세스가 소유한다.** 모델은 `pending/working/blocked/abandoned/unavailable`만 쓸 수 있고, `passed/failed`는 검증 명령을 실제로 실행한 프로세스만 설정한다(`_GATE_STATUS_CLAMP`). 모델의 self-report는 완료 근거가 되지 않는다.
- **trivial 게이트를 걸러낸다.** 변경 이전 코드(격리 워크트리)에서도 통과하는 게이트는 판별력이 없으므로 `unavailable`로 강등한다(P0-A).
- **검증이 대상을 바꾸면 무효로 본다.** 게이트 실행 전후 워크스페이스 해시가 달라지면 그 게이트는 인정하지 않는다(P0-B).
- **완료 판정은 순수 함수다.** `resolve_completion_verification`은 모델을 다시 부르지 않는다.

측정: `bench.py --run`의 `false_completion_rate`와 `gate_diagnosis`(맹점 vs 게이트 없음)로 관측한다.

## 실행 경계 (execution)

| 모드 | 격리 | 쓰기 경계 |
|---|---|---|
| `docker`(기본값) | 컨테이너 + `--network none` + 워크스페이스 마운트 | 컨테이너 경계 |
| `host`(실사용) | 없음 — 호스트 셸에서 직접 실행 | **sandbox-exec 쓰기 화이트리스트** |

host 모드에서 유일한 방벽이 정규식 블랙리스트(`_DANGEROUS`)뿐이었다. 블랙리스트는 명령 문자열 표면만 보므로 `python3 -c`·변수 치환·`find -delete` 우회가 자명하다. 그래서 방어를 **"어디에 쓸 수 있는가"**로 옮겼다(P0-C #3):

- `app/sandbox/host_guard.py`가 bash를 macOS `sandbox-exec`로 감싼다. 쓰기 허용은 워크스페이스·임시 디렉터리·`/dev` 표준 노드·패키지 캐시뿐이고, 그 밖은 OS가 거부한다.
- 읽기·네트워크·실행은 제한하지 않는다. 목표는 기밀성이 아니라 **워크스페이스 밖 변경 차단**이다.
- 파일 도구(`write_file`/`edit_file`)는 이전부터 `_resolve`가 워크스페이스 밖 경로를 `PermissionError`로 거부한다.
- 끄려면 `HOST_WRITE_GUARD=0`. macOS가 아니거나 `sandbox-exec`이 없으면 자동으로 무동작(방어를 더할 뿐, 없다고 실행을 막지 않는다).

고정 테스트: `test_host_write_guard.py` — 우회(python·변수치환·tee) 차단과 정상 명령(git·pytest) 동작을 함께 검증한다. 가드가 정상 작업을 깨면 게이트가 거짓 실패하므로 둘 다 필요하다.

## 네트워크 경계

- 서버는 `127.0.0.1`에 바인딩한다. 외부 접근은 Cloudflare Access 등 앞단 인증을 전제한다.
- `FORGE_REQUIRE_AUTH=1`이면 토큰 없이는 기동을 거부한다(fail-closed). 기본값은 `False`이며, 이는 **앞단 인증이 있는 배포를 전제로 한 운영자 결정**이다. 앞단 없이 노출하려면 반드시 켠다.
- `docker` 모드의 검증 명령은 `--network none`으로 실행한다.

## 승인 경계

`write_file`·`edit_file`·`bash`·`save_skill`·`build_frontend`는 승인 대상이다(`APPROVAL_REQUIRED`). 자동 승인(auto_approve)을 켜면 이 경계가 사라지므로, host 모드 + 자동 승인 조합에서는 위의 쓰기 화이트리스트가 실질적인 마지막 방벽이다.

## 기록에 남기는 것

- 부수효과 실행은 `tool_ledger`에 남겨 재개(resume)가 같은 부수효과를 재실행하지 않는다.
- 자동 커밋은 에이전트가 바꾼 경로만 담는다(사람이 편집 중인 변경을 쓸어담지 않는다).
- 검증 통과 완료만 durable 프로젝트 지식으로 적립한다(미검증 산출물로 기억을 오염시키지 않는다).
