## 미완 작업 (우선순위)

### 1. 하단 여백 — composer 아래 큰 빈 공간 (근본 원인 미규명)
- **증상**: 최신 배포(.0655)에 composer `padding: 8px 12px 10px`(env 제거, ignoresSafeArea 시도)가
  반영됐는데도 폰에서 composer 아래 여백이 그대로. `env(safe-area-inset-bottom)`를 제거해도
  화면 변화가 없었다 → **여백은 footer의 bottom padding이 아니라 구조적인 것**이다.
- **진단 순서** (폰 또는 인앱 브라우저 mobile 뷰에서):
  1. `document.querySelector('footer').getBoundingClientRect().bottom` vs `window.innerHeight`
     비교 → footer가 실제로 뷰포트 바닥에 닿는지 확인.
  2. 안 닿으면 `.app`(`position:fixed; inset:0`, style.css ~66줄)의 실제 높이 확인.
     iOS standalone PWA에서 `inset:0`/`height:100%`가 홈 인디케이터 영역을 포함 못 하는
     사례가 있음 — `100dvh` 또는 `-webkit-fill-available` 검토.
  3. `.composer-spacer`(style.css ~1488줄) 등 footer 내부에 높이를 더하는 요소 확인.
  4. `main`의 `padding-bottom: 32px`(style.css ~862줄)는 composer '위' 여백이라 하단과 무관 —
     헷갈리지 말 것.
- `viewport-fit=cover`는 index.html에 이미 있음(확인함). 그건 원인 아님.

### 2. 하단 탭바 ignoresSafeArea 적용 (요청됨, 미착수)
- `.sidebar-tabbar { padding-bottom: env(safe-area-inset-bottom) }`(style.css ~2174줄 부근)을
  composer와 동일하게 고정값(예: `10px`)으로. 단, 위 1번 원인이 밝혀지면 그에 맞춰.

## 이번 세션 완료분 (전부 커밋·푸시됨, origin/main)

### 배포 파이프라인 (구버전 고착 근본 해결)
- **Cloudflare Access**: 사이트 전체가 로그인 뒤라 SW의 `/sw.js` 요청이 302→SW 갱신 불가였음.
  Zero Trust → Access에 `sw.js`, `assets/*`, `index.html`, `manifest.webmanifest`,
  `workbox-*.js` **Bypass(Everyone)** 앱 추가로 해결.
- **Cloudflare 캐시**: `no-store` 무시하고 sw.js를 4h 캐시. Caching → **Purge Everything** +
  **Browser Cache TTL: Respect Existing Headers**로 해결.
- **backend**: `sw.js`/`index.html`을 `Cache-Control: no-store`로 서빙(main.py `_NO_STORE`).
- **PWA**: `registerType: 'autoUpdate'` + 포그라운드 복귀 시 `reg.update()`(main.js).
- 상세: docs/operations/troubleshooting.md "Cloudflare Access 뒤에서 PWA" 항목, memory `forge-deployment`.
